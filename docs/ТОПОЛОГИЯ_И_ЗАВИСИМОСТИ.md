# Топология и зависимости XFI Guard

XFI Guard строит карту кластера из зарегистрированных узлов Master, Entry и Exit.

## Правила

- неизвестный узел не может быть добавлен в граф;
- управление: `Master → Entry`;
- выход в Интернет: `Entry → Exit`;
- публичный management-доступ не является зависимостью;
- при нескольких отказах сначала определяется корневая неисправность;
- удаление клиентов, inbound, узлов и БД не является автоматическим действием.

## Пример

```text
Master
 ├── Entry-01 ──→ Exit-01
 ├── Entry-02 ──→ Exit-02
 └── Entry-03 ──→ Exit-01
```

Если Exit-01 недоступен, граф позволяет связать проблему с Entry-01 и Entry-03,
не создавая два независимых ложных инцидента.

## Состояния

- `неизвестно`
- `в норме`
- `есть проблемы`
- `не работает`
